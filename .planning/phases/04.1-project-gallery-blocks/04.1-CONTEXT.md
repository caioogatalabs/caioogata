<decisions>
## Implementation Decisions

### Staggered Grid Behavior
- **D-01:** Rewrite `ProjectGalleryStaggered` to render rows respecting `spans[]` from `GalleryRow`. Each row is a 12-col CSS grid where images fill their span columns. No more zigzag flattening.
- **D-02:** Row-height constraint: all rows capped at **~500px** max-height with `object-cover` on images. Prevents extremely tall images from dominating.
- **D-03:** Sharp corners — **0px radius** on all staggered gallery images. No `rounded-[12px]`. Editorial/brutalist treatment distinct from other rounded components.
- **D-04:** Tight gaps — **4px within a row**, **8px between rows**. Mosaic-like density, images feel like one continuous composition.
- **D-05:** Backward compatible — existing `en.json` rows with `spans` and `images` render correctly without any data migration.

### Full-Bleed Presentation
- **D-06:** `gallery-full-bleed` is a **layered composition**: a background image that bleeds 100vw edge-to-edge, with a foreground image centered at ~8 cols (~66% width) floating on top.
- **D-07:** Background bleed image gets a **semi-transparent overlay** (`bg-bg` at 50-70% opacity) between background and foreground. Ensures the foreground screenshot pops. Same pattern as the video overlay documented in CLAUDE.md.
- **D-08:** Background image: zero padding, zero radius, zero margin — true 100vw.
- **D-09:** New section type `gallery-full-bleed` added to `ProjectSection.type` union and the `SectionBlock` switch in `ProjectPageShell`.

### Sticky Gallery Mechanics
- **D-10:** Match fiddle.digital's stick-gallery pattern exactly: content pinned with `position: sticky; top: 0`, scroll zone container sized per slide count.
- **D-11:** **~1 viewport-height per slide** — 4 slides = ~4x viewport tall container. User scrolls one full screen per image swap.
- **D-12:** **Image-only** — no text captions in the sticky area. The gallery is purely visual; context comes from surrounding sections.
- **D-13:** Slide transitions driven by scroll position (crossfade between slides based on scroll progress within each slide's zone).
- **D-14:** New section type `gallery-stick` added to `ProjectSection.type` union and the `SectionBlock` switch.

### Entrance Animations & Motion
- **D-15:** `gallery-staggered` and `gallery-full-bleed` (foreground) use existing `useScrollReveal` clip-path animation.
- **D-16:** `gallery-stick` does NOT use scroll-reveal — the scroll-pinned swap IS the animation.
- **D-17:** Multi-image staggered rows use **staggered reveal timing**: left-to-right with 70ms delay per image (matching existing `-a-N` stagger system). Creates a wave effect across the row.
- **D-18:** All gallery types respect `prefers-reduced-motion` — instant positions, no transitions.

### Claude's Discretion
- Exact overlay opacity for full-bleed (somewhere in 50-70% range)
- Full-bleed data model: how `bgImage` and `fgImage` are specified in JSON (two image fields per section, or nested structure)
- Sticky gallery scroll-to-slide mapping curve (linear vs eased)
- Whether staggered rows need a min-height alongside the 500px max
- CSS approach for 100vw bleed within the padded layout (negative margins vs separate wrapper)
- Scroll indicator or progress dots on the sticky gallery (if any)

</decisions>

<specifics>
## Specific Ideas

- **fiddle.digital stick-gallery** is the direct reference for the sticky gallery implementation — match its scroll-pinned behavior
- **Sharp corners + tight gaps** on staggered grid creates a distinctly brutalist photo mosaic feel, differentiating gallery from rounded UI components
- **Full-bleed as layered composition** (bg bleed + fg centered) is more sophisticated than a simple edge-to-edge image — creates cinematic "stage" moments
- **Overlay pattern reuse** from CLAUDE.md video background overlay — same `bg-bg` semi-transparent technique applied to full-bleed background
- **Stagger reveal wave** across multi-image rows adds visual rhythm without being distracting — proven pattern from existing `-a-N` system

</specifics>
