## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap within staggered gallery rows (D-04) |
| sm | 8px | Gap between staggered gallery rows (D-04) |
| md | 16px | Mobile section side padding (`px-5` = 20px is closest, keep existing) |
| lg | 24px | Section vertical padding base unit |
| xl | 32px | Tablet section side padding (`px-8` = 32px) |
| 2xl | 48px | Not used in this phase |
| 3xl | 64px | Desktop section side padding (`px-16` = 64px) |

Exceptions:
- `gallery-full-bleed` uses **0px padding** on all sides for background image (breaks standard section padding intentionally)
- `gallery-full-bleed` foreground image is centered at **8 columns (~66% width)** with auto margins
- `gallery-stick` container height is **100vh per slide** (e.g. 4 slides = 400vh)

Inherited Tailwind utilities (not new spacing tokens):
- `py-24` (96px) on staggered section — pre-existing pattern across all project page sections, not introduced by this phase

### Full-Bleed Overlay Contract

The full-bleed background overlay uses the established Video Background Overlay Pattern from CLAUDE.md, adapted:

| Property | Value | Source |
|----------|-------|--------|
| Background class | `bg-bg` | Semantic token, adapts to data-theme |
| Opacity | `0.6` (60%) | Claude's discretion area (D-06 range: 50-70%). 60% chosen: darker than 50% for clear fg separation, lighter than 70% to preserve bg atmosphere |
| Position | `absolute inset-0` between background image and foreground image | DOM order, no z-index needed |
| Overflow | No `overflow-hidden` on overlay | CLAUDE.md rule |

## Component Inventory

### 1. `gallery-staggered` (Rewrite)

| Property | Value |
|----------|-------|
| Grid system | CSS `grid-template-columns: repeat(12, 1fr)` per row |
| Row gap | 8px (`--primitive-space-2`) between rows |
| Column gap | 4px (`--primitive-space-1`) within rows |
| Image radius | **0px** — sharp corners, brutalist treatment (D-03) |
| Image height | Natural aspect ratio with `max-height: 500px` and `object-cover` (D-02) |
| Image min-height | 200px — prevents collapsed rows on very wide images |
| Section padding | `px-5 md:px-8 lg:px-16` (standard section padding) |
| Section vertical | `py-24` (96px top and bottom) |
| Entrance animation | `useScrollReveal` clip-path per image (D-15) |
| Stagger timing | 70ms delay per image index within a row, left-to-right (D-17) |
| Reduced motion | Instant reveal, no stagger delay (D-18) |

**Span-to-column mapping:**

| `spans[]` | Grid columns | Example |
|-----------|-------------|---------|
| `[12]` | `col-span-12` | Single full-width image |
| `[6, 6]` | `col-span-6` + `col-span-6` | Two equal images |
| `[4, 4, 4]` | `col-span-4` x3 | Three equal images |
| `[8, 4]` | `col-span-8` + `col-span-4` | Asymmetric pair |
| `[4, 8]` | `col-span-4` + `col-span-8` | Inverse asymmetric |

**Row rendering rule:** Each `GalleryRow` becomes one CSS grid row. Images within a row fill their respective span columns. Rows stack vertically with 8px gap. No zigzag. No flattening.

### 2. `gallery-full-bleed` (New)

| Property | Value |
|----------|-------|
| Background image | 100vw edge-to-edge, zero padding, zero radius, zero margin (D-08) |
| Background sizing | `width: 100vw; position: relative; left: 50%; transform: translateX(-50%)` to break out of padded parent |
| Background fit | `object-cover`, natural aspect ratio |
| Overlay | `bg-bg` div at 60% opacity, `absolute inset-0` (see Color section) |
| Foreground image | Centered at 8/12 columns (~66% width), `max-width: 66.666%`, `margin: 0 auto` |
| Foreground offset | Vertically centered over background with `py-[12%]` padding on the foreground wrapper |
| Foreground radius | 12px (`--radius-component-md`) — foreground gets standard component rounding to contrast with bleed bg |
| Foreground shadow | None (depth via tonal stacking only, per Design.md rule) |
| Entrance animation | Foreground only: `useScrollReveal` clip-path (D-15). Background has no entrance — it is always visible |
| Reduced motion | Instant foreground reveal (D-18) |
| Section type | `'gallery-full-bleed'` added to `ProjectSection.type` union |

**DOM structure:**
```
section.relative (no padding — full-bleed breaks layout)
  div.relative (100vw bleed container)
    img (background, object-cover, w-full)
    div.absolute.inset-0.bg-bg (overlay, opacity 0.6)
  div.relative.z-10.mx-auto (foreground container, max-w-[66.666%])
    div (useScrollReveal wrapper)
      img (foreground, rounded-[12px])
```

### 3. `gallery-stick` (New)

| Property | Value |
|----------|-------|
| Container height | `100vh * slideCount` (D-11: 1 viewport per slide) |
| Sticky element | `position: sticky; top: 0; height: 100vh` (D-10) |
| Image sizing | Full viewport, `object-cover`, `width: 100%; height: 100vh` |
| Image radius | 0px — full-bleed pinned images, no rounding |
| Image padding | 0px — edge-to-edge within the viewport |
| Transition | Crossfade between slides: `opacity` transition driven by scroll progress (D-13) |
| Transition curve | Linear mapping from scroll position to opacity (Claude's discretion — linear is predictable for scrubbing) |
| Scroll zone | Each slide occupies `1/slideCount` of the total container scroll distance |
| Entrance animation | None — the scroll-pinned swap IS the animation (D-16) |
| Reduced motion | All slides visible stacked (no crossfade, no sticky pin) — falls back to vertical image stack (D-18) |
| Section type | `'gallery-stick'` added to `ProjectSection.type` union |
| Scroll indicator | None — no progress dots or indicators (Claude's discretion: gallery is purely visual, indicators add UI clutter inconsistent with brutalist aesthetic) |

**DOM structure:**
```
div.relative (height: slideCount * 100vh)
  div.sticky.top-0.h-screen.overflow-hidden
    img[0] (absolute inset-0, opacity driven by scroll)
    img[1] (absolute inset-0, opacity driven by scroll)
    img[N] (absolute inset-0, opacity driven by scroll)
```

**Scroll-to-opacity mapping:**
- Slide N is fully visible when scroll progress is in range `[N/total, (N+1)/total]`
- Crossfade zone: last 20% of each slide's range overlaps with next slide's first 20%
- First slide starts at opacity 1, last slide ends at opacity 1

## Data Model Extensions

### `ProjectSection.type` union update

```typescript
type: 'hero' | 'challenge' | 'impact' | 'gallery-staggered' | 'gallery-feature-list' | 'gallery-full-detail' | 'info' | 'gallery-full-bleed' | 'gallery-stick'
```

### `gallery-full-bleed` data shape (Claude's discretion)

```typescript
// Two image fields on ProjectSection — flat, not nested
{
  type: 'gallery-full-bleed',
  bgImage: string,        // background bleed image path
  fgImage: string,        // foreground centered image path
  bgAlt?: string,         // background alt text
  fgAlt?: string,         // foreground alt text
}
```

Rationale: Flat fields over nested object — simpler JSON authoring, consistent with existing `image?: ProjectImage` pattern on ProjectSection.

### `gallery-stick` data shape (Claude's discretion)

```typescript
// Reuses existing rows pattern — each row has one image = one slide
{
  type: 'gallery-stick',
  rows: GalleryRow[],     // each row = 1 slide, first image used
}
```

Rationale: Reuse `GalleryRow` rather than inventing a new `slides[]` array. The `spans` field is ignored for sticky (images are always full-viewport), but the type stays compatible.

## Interaction States

| Gallery Type | Hover | Focus | Active | Loading |
|-------------|-------|-------|--------|---------|
| gallery-staggered | None | None | None | `loading="lazy"` on all `<img>` |
| gallery-full-bleed | None | None | None | `loading="lazy"` on both images |
| gallery-stick | None | None | None | `loading="lazy"` on slides after first; first slide `loading="eager"` |

No hover, focus, or active states. These are passive visual content blocks. Keyboard parity is not applicable — there are no interactive elements to navigate.

## Responsive Behavior

### gallery-staggered

| Breakpoint | Behavior |
|------------|----------|
| Mobile (<768px) | All spans collapse to `col-span-12` (single column stack) |
| Tablet (768-1023px) | Spans render as declared, but minimum 6-col per image (e.g. `[4,4,4]` becomes `[6,6] + [12]`) |
| Desktop (1024px+) | Spans render exactly as declared in JSON |

### gallery-full-bleed

| Breakpoint | Behavior |
|------------|----------|
| Mobile (<768px) | Background still 100vw; foreground expands to 90% width (from 66%) |
| Tablet (768-1023px) | Background 100vw; foreground at 75% width |
| Desktop (1024px+) | Background 100vw; foreground at 66% width |

### gallery-stick

| Breakpoint | Behavior |
|------------|----------|
| Mobile (<768px) | Falls back to vertical image stack (no sticky pin — `position: relative` instead of `sticky`). Height returns to `auto`. |
| Tablet (768-1023px) | Sticky behavior active, full viewport |
| Desktop (1024px+) | Sticky behavior active, full viewport |

## Performance Budget

| Metric | Target |
|--------|--------|
| Image format | WebP preferred, JPEG fallback (existing pattern) |
| Lazy loading | All images `loading="lazy"` except first visible in viewport |
| Max images per gallery-staggered | No hard limit, but recommend <= 12 per section |
| Sticky gallery max slides | Recommend <= 6 (6 * 100vh = 600vh scroll) |
| rAF usage | `useScrollReveal` already uses rAF with ticking guard — reuse, do not duplicate |
| Sticky scroll driver | New hook or inline rAF with same ticking pattern as `useScrollReveal`/`useScrollExpand` |
