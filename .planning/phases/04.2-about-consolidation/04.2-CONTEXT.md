# Phase 04.2: About Consolidation - Context

**Gathered:** 2026-04-25
**Status:** Ready for planning

<domain>
## Phase Boundary

Consolidate three V2 content concepts — **Skills**, **Notable Clients**, **Education** — as numbered subsections inside `/about`, replacing the standalone `/skills` route. The `/about` page becomes a single rich, editorial-style biography page divided into numbered sections (`1.1 / Bio`, `1.2 / Skills`, `1.3 / Notable Clients`, `1.4 / Education`) — inspired by the Lucas Berghoef portfolio reference (numbered editorial sections separated by horizontal dividers).

**Scope is V2 only.** V1 components (`Skills.tsx`, `Education.tsx`, `Clients.tsx` under `src/components/sections/`) are NOT touched. V1 routes remain intact for the production V1 site. All work happens within V2 components, V2 routes, and V2 content fields.

The `/skills` V2 route and `SkillsSection.tsx` V2 component (with the SVG case-study relationship map) are deleted — that complexity is replaced by a simpler `SkillsBlock` inside `/about`.

The home/menu loses the `skills`, `education`, and `clients` entries — they're no longer destinations of their own.

</domain>

<decisions>
## Implementation Decisions

### Page Architecture

- **D-01:** `/about` becomes the single destination for biographical content. The hero (scroll-driven video + headline "Bridging brand strategy...") is preserved untouched. After the hero, the page renders four numbered subsections in order: `1.1 / Bio`, `1.2 / Skills`, `1.3 / Notable Clients`, `1.4 / Education`.
- **D-02:** The `/skills` route is deleted: remove `src/app/skills/page.tsx` and `src/components/sections/v2/SkillsSection.tsx` (with its SVG relationship map). Reusable constants (`LEVEL_WIDTH`) are copied into the new `SkillsBlock`.
- **D-03:** The home menu in `src/content/en.json` (`menu.items`) is trimmed: remove the `skills`, `education`, and `clients` entries. The remaining items are `about`, `projects`, `experience`, `philosophy`, `contact`. The corresponding `previews/*.webp` for removed items can stay (no harm) or be deleted.

### Section Divider Pattern

- **D-04:** A new atomic component `SectionDivider` renders a horizontal rule with the section number + label on the left (`1.1 / Bio`, `1.2 / Skills`, etc). No email, no year, no right-aligned metadata — that responsibility stays with the global Welcome Bar in IntroSection.
- **D-05:** Divider typography: monospace label, small (`text-xs`), uppercase letter-spacing matching the existing Welcome Bar pattern. Aligns to the 12-col grid (`px-5 md:px-8 lg:px-16`).
- **D-06:** Divider color: `border-border-secondary` for the rule itself, `text-text-tertiary` for the label.

### 1.1 / Bio Block

- **D-07:** Reuses the existing content zone of the current `AboutSection` — `6-6` grid: left column = Core Expertise list with dividers, right column = bio paragraphs. No content rewrite. The new `BioBlock` extracts this from `AboutSection.tsx` into its own focused file.
- **D-08:** A `SectionDivider` labeled `1.1 / Bio` renders immediately above the bio's content zone, after the video hero ends.

### 1.2 / Skills Block

- **D-09:** Layout: `6-6` — left column has the **category label** (e.g., "Design Systems"), right column has the list of skills in that category, each rendered as: skill name + nivel bar + level label. Six categories stack vertically; each category is its own `6-6` row with a thin divider between categories.
- **D-10:** Skill bar: divider line as track + filled segment matching `LEVEL_WIDTH` (Expert 95%, Advanced 75%, Proficient 55%, Familiar 35%). Same percentages as `SkillsSection.tsx` — values copied, SVG removed.
- **D-11:** No "Case Studies" column, no SVG bezier connecting lines, no bidirectional hover. Just static skills + bars.
- **D-12:** Existing `skill.projectSlugs` data in `en.json` stays in the JSON (cheap to keep, no rendering cost) but is unused in V2. Future ideas can reuse it.
- **D-13:** Source data: existing `content.skills.categories` in `en.json` (no schema change).

### 1.3 / Notable Clients Block

- **D-14:** Short description text in 6-col right column above the logo grid: a single sentence ("Two decades of work for brands across Brazil and beyond." or similar — Claude can refine within constraints). Added as a new field `clients.shortDescription` in `en.json` to avoid changing V1's longer `clients.description`.
- **D-15:** Logo grid: 4-column layout (`3-3-3-3`) of 16 client logos. With 16 items, exactly 4 rows × 4 columns.
- **D-16:** Cell styling: **no border, no background fill** on the cells themselves. Instead, use thin **divider lines between rows and between columns** — table-style. Sharp corners (0px radius) per V2 gallery rule. No shadows. Tonal stacking only.
- **D-17:** Cell sizing: `min-h-[120px]` to give logos breathing room. Logo image centered with `object-contain max-h-[44px] max-w-[108px]`. Reuse the `CLIENT_LOGOS` SVG paths from `src/components/sections/Clients.tsx` (V1) — copy the lookup map into the V2 component, do not import from V1.
- **D-18:** Source data: existing `content.clients.list` (16 brand names) + the new `content.clients.shortDescription`.

### 1.4 / Education Block

- **D-19:** Layout: `6-6` — left column **empty**, right column contains an inner `2-10` sub-grid per row: year on the left as a timeline column, info (institution + degree + location + optional note) stacked on the right.
- **D-20:** Single chronological reverse list combining `education.items` (formal) and `education.additional` (training). Sorted by latest year. No sub-headers separating formal vs additional.
- **D-21:** Each row separated by a thin divider (`border-border-secondary`). Sharp corners. No card backgrounds, no dotted borders (V1 used dotted; V2 ditches them).
- **D-22:** Year format: just the latest year of the range (e.g., "2005" for "2001 - 2005"; "2026" for the most recent training). Year column is monospace (`font-mono`) to feel like a timeline stamp; institution + degree use `var(--font-sans)` (Fabio XM).
- **D-23:** Source data: existing `content.education.items` + `content.education.additional` (no schema change).

### Component Architecture

- **D-24:** New directory `src/components/sections/v2/about/` holds:
  - `SectionDivider.tsx` — reusable atom for `1.X / Label`
  - `BioBlock.tsx` — extracted bio + Core Expertise content zone
  - `SkillsBlock.tsx` — simplified skills list (no SVG)
  - `ClientsBlock.tsx` — `3-3-3-3` logo grid with table dividers
  - `EducationBlock.tsx` — timeline-style education list
- **D-25:** `AboutSection.tsx` is refactored to keep its hero (video + sticky overlay) intact and orchestrate the four new blocks below: `<SectionDivider/> + <BioBlock/> + <SectionDivider/> + <SkillsBlock/> + …`. The `useScrollVideo` and existing scroll transitions stay.
- **D-26:** Directory matches the existing pattern under `src/components/sections/v2/project/` (sub-page-specific components grouped under their parent).

### Content Updates

- **D-27:** `src/content/en.json` and `src/content/pt-br.json`:
  - Remove from `menu.items`: `skills`, `education`, `clients` entries.
  - Add `clients.shortDescription`: a one-sentence short version (kept in addition to existing `description` for V1 compatibility).
  - No other content changes.

### Theming

- **D-28:** Page theme stays dark (default, no `data-theme` override). All four blocks render in dark mode using semantic tokens (`bg-bg`, `text-text-primary`, `border-border-secondary`, etc).

### Animations

- **D-29:** Each block uses `useInView` + `-entrance -slide-up` on its main content for the standard V2 entrance pattern. Stagger via `-a-0` … `-a-5` on stacked children where appropriate.
- **D-30:** `prefers-reduced-motion` respected — all entrances become instant.

### Claude's Discretion

- Exact short description copy for `clients.shortDescription` (one sentence, EN + PT-BR).
- Exact spacing between blocks (`py-16`, `py-24`, etc) — should feel editorial, not cramped.
- Whether to add a thin tonal background shift on alternate blocks (for subtle hierarchy) or keep flat dark — preference is flat unless visual rhythm clearly suffers.
- Order of fields inside an Education row (institution first or degree first).
- Mobile collapse behavior of the `3-3-3-3` clients grid (probably `2 cols` on mobile, `4 cols` on desktop).
- Whether the `pt-br.json` short description is translated or remains EN (to be addressed in plan).

</decisions>
