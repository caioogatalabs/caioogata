## Decisions Made

- **LEVEL_WIDTH duplication strategy:** Inlined the four-entry map directly into SkillsBlock instead of refactoring it into a shared util. Reason: Wave 3 is removing the source file (`SkillsSection.tsx`); a shared util would only be reused if a Wave 4+ feature needs the same widths, which is not on the roadmap. Two duplicate copies for two days is cheaper than premature abstraction.
- **Tailwind classes for bar styling instead of `var(--color-...)`:** The old `SkillsSection.tsx` used inline `style={{ backgroundColor: 'var(--color-border-primary)' }}`. I replaced this with `bg-border-secondary` (track) and `bg-text-primary` (fill) Tailwind utilities — V2 norm per CLAUDE.md §Component Patterns ("Always use `text-text-primary`, `bg-bg-surface-primary` etc"). Used `border-secondary` rather than `border-primary` because the divider lines between rows already use `border-border-secondary`, keeping bar tracks visually subordinate.
- **`!px-0` override on inner Grid:** The outer wrapper already applies `px-5 md:px-8 lg:px-16`; the inner `Grid` component's default `px-5 md:px-8 lg:px-16` would double-pad. `!px-0` neutralizes it without rewriting Grid.
- **Stagger index clamp at 19:** With 6 categories the cap never bites in practice, but matches the established `-a-0 .. -a-20` CSS range and protects against future content additions.
- **First category keeps its top border:** Per plan instructions, the deliberate editorial style is consistent with BioBlock's Core Expertise list — every row has a top border, no `:first-child` override.
