    **Cell border logic decision (W6 — Option A, static lookup):**
    Per CLAUDE.md §Component Patterns ("Static class maps over dynamic Tailwind class strings"), define a static `CELL_BORDERS: string[]` lookup keyed by index in the 4×4 desktop grid (16 entries, one per logo). Each entry encodes the responsive border classes for that cell — desktop borders use `lg:` prefix, mobile borders use the unprefixed class. This replaces the previous fragile inline-conditional-class-array pattern.

    Border rules encoded in CELL_BORDERS:
    - Desktop (4×4 grid): `border-r` on cells where colIndex < 3 (cells 0,1,2,4,5,6,8,9,10,12,13,14 → 12 cells); `border-t` on cells where rowIndex > 0 (cells 4..15 → 12 cells).
    - Mobile (2-col grid, 8 rows): `border-r` on even-indexed cells (col 0); `border-t` on cells where index >= 2 (rows 1..7).
    - Mobile classes are unprefixed; desktop classes use `lg:` to override at the breakpoint.

    Concrete CELL_BORDERS table (compute by hand, 16 entries):
    ```typescript
    /**
     * Border classes per cell index in the 16-cell logo grid.
     * Desktop: 4×4 (cells 0..15). Mobile: 2×8.
     * Encodes: right divider on cells whose desktop colIndex < 3 OR mobile colIndex == 0;
     *          top divider on cells whose desktop rowIndex > 0 OR mobile rowIndex > 0.
     */
    const CELL_BORDERS: string[] = [
      // index 0  | desktop (col 0, row 0): r       | mobile (col 0, row 0): r       → 'border-r border-border-secondary lg:border-r lg:border-t-0'  but row 0 has no top — confirm below
      'border-r border-border-secondary lg:border-r',                              // 0  desktop r;        mobile r
      'border-border-secondary lg:border-r lg:border-border-secondary',            // 1  desktop r;        mobile (no r — col 1 last)
      'border-r border-border-secondary lg:border-r lg:border-t border-t lg:border-t-0',  // 2  desktop r;        mobile r + t (row 1)
      'border-border-secondary lg:border-r-0 lg:border-t border-t',                // 3  desktop last col; mobile (no r) + t
      // index 4..7 (desktop row 1, all cells get top border on lg; mobile rows 2-3)
      'border-r border-border-secondary border-t lg:border-r lg:border-t',         // 4  desktop r + t;    mobile r + t (row 2)
      'border-border-secondary border-t lg:border-r lg:border-t',                  // 5  desktop r + t;    mobile (no r) + t
      'border-r border-border-secondary border-t lg:border-r lg:border-t',         // 6  desktop r + t;    mobile r + t (row 3)
      'border-border-secondary border-t lg:border-r-0 lg:border-t',                // 7  desktop t only;   mobile (no r) + t
      // index 8..11 (desktop row 2; mobile rows 4-5)
      'border-r border-border-secondary border-t lg:border-r lg:border-t',         // 8  desktop r + t;    mobile r + t (row 4)
      'border-border-secondary border-t lg:border-r lg:border-t',                  // 9
      'border-r border-border-secondary border-t lg:border-r lg:border-t',         // 10
      'border-border-secondary border-t lg:border-r-0 lg:border-t',                // 11
      // index 12..15 (desktop row 3; mobile rows 6-7)
      'border-r border-border-secondary border-t lg:border-r lg:border-t',         // 12
      'border-border-secondary border-t lg:border-r lg:border-t',                  // 13
      'border-r border-border-secondary border-t lg:border-r lg:border-t',         // 14
      'border-border-secondary border-t lg:border-r-0 lg:border-t',                // 15
    ]
    ```

    **Important:** When implementing, simplify the per-cell strings to the minimum needed — the executor should derive each entry from these rules:
    - Mobile right border: `index % 2 === 0` → include `border-r border-border-secondary`; else just `border-border-secondary` (the token still needs to be on the cell so any same-class lg: override picks the color).
    - Mobile top border: `index >= 2` → include `border-t`.
    - Desktop right border (overrides at lg): `index % 4 < 3` → include `lg:border-r`; else `lg:border-r-0` (kill the mobile right that would otherwise show on lg col 3 — happens at index 3, but at lg, col 3 is the last desktop col, so we strip the right border).
    - Desktop top border: `Math.floor(index / 4) > 0` → include `lg:border-t`; else (row 0 desktop) the cell shouldn't have a top border on desktop. If mobile gave it `border-t` (e.g., index 2 falls in mobile row 1 but desktop row 0), the cell needs `lg:border-t-0` to strip it. Index 2 and 3 are in mobile row 1 (top border on) but desktop row 0 (top border off), so they need `lg:border-t-0`.

    Executor note: rather than hand-pasting the array above, derive it programmatically inside the file at module top-level (a build-time loop is fine — Tailwind only sees the literal string portions, but we can avoid Tailwind's JIT issue by listing all the literal classes in a "safelist" comment AND using only literal strings in the array). Since `border-r`, `border-r-0`, `lg:border-r`, `lg:border-r-0`, `border-t`, `border-t-0`, `lg:border-t`, `lg:border-t-0`, `border-border-secondary` are all literal Tailwind utilities, the simplest approach is: write a helper `function cellBorderClass(i: number): string` that returns a literal-class-only string per the rules above. No template literals with computed parts — all the `border-*` tokens are literal in the source. Tailwind will pick them up because each literal appears in the source.
